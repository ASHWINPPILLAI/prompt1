# AutoCoT: Automatic Chain-of-Thought demonstration generation

## Procedure (per docs/autocot.md from the spec)

1. **Embed dev questions**: Use the same MiniLM embedder as the retrieval index.
   - Source: `eval/rag_dev.jsonl`, answerable questions only (`answerable == true`).
   - Embed each question's text.

2. **Cluster with k-means** (`k=4`, `seed=42`):
   - Use `sklearn.cluster.KMeans(n_clusters=4, random_state=42)`.
   - Identify the question nearest each cluster centroid (minimum Euclidean distance).

3. **Generate reasoning**:
   - For each of the 4 selected questions, retrieve context (`top_k=5`) and generate
     reasoning with `temperature=0.7`, using this zero-shot trigger:
     > "{context}\n\nQuestion: {question}\n\nLet's think step by step."
   - This is a zero-shot CoT prompt — no examples given.

4. **Filter** (accept only if ALL conditions pass):
   - Reasoning has at most **6 steps**, each step at most **40 words**.
   - Token-level F1 of the generated final answer against the gold span ≥ **0.5**.
   - The reasoning cites at least one **section_id** (contains `#`).

5. **Fallback**: If a candidate fails, take the **next nearest question** in the same
   cluster and try again. Log all accepted and rejected candidates in
   `results/autocot_log.json`.

6. **HUMAN gate**: Read the 4 accepted demonstrations in `prompts/autocot_demos.yaml`
   and reject any that look wrong or misleading before running E3.

## Output format (`prompts/autocot_demos.yaml`)

```yaml
# Auto-generated by scripts/autocot_build.py — do NOT edit by hand.
# HUMAN: review and reject any bad demonstrations before using v4b.
demos:
  - cluster: 0
    question: "..."
    doc_id: "..."
    answer: "..."
    reasoning:
      - "Step 1: ..."
      - "Step 2: ..."
    section_ids: ["doc_id#section"]
    f1_score: 0.72
    accepted: true
```

## Why AutoCoT?

Hand-writing CoT demonstrations requires domain expertise and time. AutoCoT (Zhang et al.
2022) shows that clustering questions and using a zero-shot trigger produces demonstrations
of comparable quality. This experiment tests that claim on the Doc2Dial domain.

## Known limitations

- k=4 clusters may not cover all question types; increase k if the dev set is large enough.
- Auto-generated reasoning can be wrong; the quality filters reduce but don't eliminate errors.
- The HUMAN gate is the final safeguard.
